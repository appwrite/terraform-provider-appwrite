# Resource: appwrite_escalation

Manages an escalation of an Appwrite organization: who a monitor's firing alert notifies, step by step, until a member acknowledges it.

A monitor uses an escalation when its `escalation_id` names it. While the monitor's alert fires, each step waits its `delay` and then notifies the members holding its `roles` and those named in `user_ids`, by email, push and in the console, until a member acknowledges the alert or it resolves. With `repeat`, the steps run again from the first, a monitor's cooldown after the last step.

An organization API key with `escalations.read` and `escalations.write` scopes is required. Configure it with the provider's `organization_api_key` attribute or `APPWRITE_ORGANIZATION_API_KEY`. Set `organization_id` on the provider or on this resource.

An escalation that a monitor uses cannot be deleted. Terraform destroys a monitor before the escalation it references, so destroying both together works; to destroy only the escalation, point its monitors elsewhere first. Alerts already escalating keep the steps they started with when the escalation changes.

## Example Usage

```terraform
resource "appwrite_escalation" "on_call" {
  name = "On call"

  steps = [
    { roles = ["owner"] },
    { delay = 900, roles = ["developer"], user_ids = [var.on_call_user_id] },
  ]

  repeat = 1
}

variable "on_call_user_id" {
  type = string
}
```

## Schema

### Required

- `name` (String) The escalation name, up to 128 characters.
- `steps` (Attributes List) The steps notified in order while nobody acknowledges the alert, up to 100. Each needs at least one of roles or user_ids. (see [below for nested schema](#nestedatt--steps))

### Optional

- `id` (String) The escalation ID. Generated when not set. Changing this forces a new resource to be created.
- `organization_id` (String) The Appwrite organization ID. Defaults to the provider-level organization_id. Changing this forces a new resource to be created.
- `repeat` (Number) How many more times the steps run from the first while nobody acknowledges the alert, from 0 to 9. Each round starts a monitor's cooldown after the last step. Defaults to 0.

### Read-Only

- `created_at` (String) The escalation creation timestamp in ISO 8601 format.
- `updated_at` (String) The escalation last update timestamp in ISO 8601 format.

<a id="nestedatt--steps"></a>
### Nested Schema for `steps`

Optional:

- `delay` (Number) Seconds to wait before notifying this step, from 0 to 2592000: after the alert fires for the first step, after the previous step for the others. Defaults to 0.
- `roles` (List of String) Organization roles, such as owner or developer, whose confirmed members this step notifies. Defaults to none.
- `user_ids` (List of String) IDs of organization members who accepted their invitation, notified by this step whatever their role. Defaults to none.

## Import

Using `terraform import` with an organization and escalation ID:

```shell
terraform import appwrite_escalation.on_call organization-id/on-call
```

When `organization_id` is configured on the provider, the escalation ID alone can be used:

```shell
terraform import appwrite_escalation.on_call on-call
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_escalation.on_call
  id = "organization-id/on-call"
}
```
