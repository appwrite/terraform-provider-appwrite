# Resource: appwrite_auth_team_membership

Manages a user's membership of an Appwrite team. Because the provider authenticates with an API key, Appwrite confirms the membership immediately and sends no invitation. Identify the member by exactly one of user_id, email or phone. Given an email address or phone number that belongs to no user, Appwrite creates one; destroying the membership does not delete that user.

## Example Usage

```terraform
resource "appwrite_auth_team" "engineering" {
  name = "Engineering"
}

resource "appwrite_auth_user" "jane" {
  name  = "Jane Doe"
  email = "jane@example.com"
}

# An existing user, by ID.
resource "appwrite_auth_team_membership" "jane" {
  team_id = appwrite_auth_team.engineering.id
  user_id = appwrite_auth_user.jane.id
  roles   = ["owner", "developer"]
}

# By email address. Appwrite adds the user with this address, or creates one
# named `name` if there is none.
resource "appwrite_auth_team_membership" "contractor" {
  team_id = appwrite_auth_team.engineering.id
  email   = "contractor@example.com"
  name    = "Contractor"
  roles   = ["developer"]
}
```

## How Appwrite handles the member

The provider authenticates with an API key, and Appwrite treats a membership
created that way as already accepted:

- `confirm` is `true` and `joined_at` is set straight away. No invitation email
  or SMS is sent, and no redirect URL is needed, so the resource takes none.
- Given `email` or `phone`, Appwrite looks for a user with that address or
  number. If there is none, it **creates a user**, named `name` (or the email
  address when `name` is unset). Destroying the membership does not delete that
  user; manage it with [appwrite_auth_user](auth_user.md) if you want Terraform
  to own it, and reference it with `user_id` instead.
- `email`, `phone` and `name` are what the membership was created from and are
  not read back. The member's current details are in `user_name`, `user_email`
  and `user_phone`.
- A user can belong to a team only once. Creating a second membership for the
  same user fails, and the error names the existing membership's import ID.

Only `roles` can change in place. Roles are matched as a set, so their order
does not matter.

## Schema

### Required

- `roles` (Set of String) The member's roles in the team, which permissions refer to as team:TEAM_ID/ROLE. May be empty. Order does not matter. Updated in place.
- `team_id` (String) The ID of the team. Changing this forces a new resource to be created.

### Optional

- `email` (String) The email address of the member. Appwrite adds the user with this address, or creates one if there is none. Appwrite matches it in lowercase. Not read back: a later change to the user's address shows in user_email, not here. Changing this forces a new resource to be created.
- `name` (String) The name to give the user Appwrite creates when email or phone matches no user. Ignored when the user already exists. Defaults to the email address, or no name for a phone number. Changing this forces a new resource to be created.
- `phone` (String) The phone number of the member, in E.164 format such as +16175551212. Appwrite adds the user with this number, or creates one if there is none. Not read back: a later change to the user's number shows in user_phone, not here. Changing this forces a new resource to be created.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `user_id` (String) The ID of an existing user to add to the team. When the member is given by email or phone instead, this is the ID of the user Appwrite matched or created. Changing this forces a new resource to be created.

### Read-Only

- `confirm` (Boolean) Whether the user has joined the team. Always true for a membership created by this resource; an imported membership may still be a pending invitation.
- `created_at` (String) The membership creation timestamp in ISO 8601 format.
- `id` (String) The membership ID, assigned by Appwrite.
- `joined_at` (String) When the user joined the team, in ISO 8601 format. Empty for a pending invitation.
- `updated_at` (String) The membership last update timestamp in ISO 8601 format.
- `user_email` (String) The member's current email address.
- `user_name` (String) The member's current name.
- `user_phone` (String) The member's current phone number.

## Import

Import is supported using the following syntax:

```shell
terraform import appwrite_auth_team_membership.jane <team-id>/<membership-id>
```

Import cannot tell whether a membership was created from a user ID, an email
address or a phone number, so it leaves `email`, `phone` and `name` empty. If
the configuration sets `email` or `phone`, the first apply after import records
it in state without replacing the membership, after checking it belongs to the
membership's user.
