# Resource: appwrite_project_services

Enables and disables the API services of a project. Each service is managed only when its attribute is set. Requests made with an API key, including the provider's own, are not blocked by a disabled service; it applies to requests from users and guests.

Each attribute is optional, and a service whose attribute is left out is not managed: it keeps whatever setting it has, and a change made to it in the Console is not reported. Setting an attribute manages that service. Removing the attribute later enables the service again, which is Appwrite's default for every service. Destroying the resource enables every service it manages and leaves the rest as they are.

Declare at most one of these per project. Two would overwrite each other's settings on every apply.

~> **Note:** A disabled service turns away requests from users and guests, such as the ones the client SDKs make. Requests made with an API key are let through, and so are Console users. That includes the provider's own requests, so disabling `project` or `tablesdb` does not stop Terraform from managing them. It also includes server-side code holding a key, so disabling a service is not a way to keep data away from it.

~> **Note:** The `graphql` service is not the GraphQL endpoint. On Appwrite 2.2.0, disabling it does not stop requests to `/v1/graphql`. To switch off GraphQL, set `graphql = false` on [appwrite_project_protocols](project_protocols.md).

A standard project API key with `project.read` and `project.write` scopes is required. Configure it with the provider's `api_key` attribute or `APPWRITE_API_KEY`.

## Example Usage

```terraform
# A server-side project: clients never sign in or upload, so the services
# they would call are switched off. Services left out are not managed.
resource "appwrite_project_services" "example" {
  account   = false
  storage   = false
  messaging = false

  # Explicitly kept on. Removing a line later enables the service again.
  tablesdb  = true
  functions = true
}
```

### Optional

- `account` (Boolean) Whether the Account service is enabled. Users call it to sign up, sign in and manage their own account. Left unset, the service is not managed; removing the attribute from the configuration enables it again.

- `messaging` (Boolean) Whether the Messaging service is enabled. Left unset, the service is not managed; removing the attribute from the configuration enables it again.
- `migrations` (Boolean) Whether the Migrations service is enabled. Left unset, the service is not managed; removing the attribute from the configuration enables it again.
- `project` (Boolean) Whether the Project service is enabled. Left unset, the service is not managed; removing the attribute from the configuration enables it again.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.

## Import

Using `terraform import` with a project ID:

```shell
terraform import appwrite_project_services.example project-id
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_project_services.example
  id = "project-id"
}
```

Importing records the setting of every service the project reports. If the configuration leaves a service out, the next plan removes it from state, and applying that plan enables the service.
