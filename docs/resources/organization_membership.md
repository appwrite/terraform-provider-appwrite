# Resource: appwrite_organization_membership

Adds a member to an Appwrite organization and manages their roles.

Organization memberships are available on Appwrite Cloud. An organization API key with `organization.memberships.read` and `organization.memberships.write` scopes is required, and only an organization owner can create a key with `organization.memberships.write`. Configure it with the provider's `organization_api_key` attribute or `APPWRITE_ORGANIZATION_API_KEY`. Set `organization_id` on the provider or on this resource.

## Adding a member

A member added with an API key joins straight away. Appwrite sends no invitation email and nobody has to accept anything, so `confirm` is `true` once the resource is created.

- **By `user_id`**, the account must already exist.
- **By `email`**, Appwrite adds the account that uses that address. If no account uses it, Appwrite creates one with a random password and still sends no email. That person has to recover the password for the address before they can sign in. Destroying the membership does not delete the account.

If the account already has a pending invitation sent from the Console, Appwrite confirms that invitation instead of creating a new membership, and the provider then sets `roles` to the configured ones. If the account is already a member, creating the resource fails; import the existing membership instead.

## Roles

`roles` is updated in place. The organization roles are `owner`, `developer`, `editor`, `analyst` and `billing`. On plans that support them, a role can be limited to one project with the form `project-<project_id>-<role>`, for example `project-my-app-developer`.

A key with `organization.memberships.write` that was issued before Appwrite restricted that scope to owners cannot grant `owner`. Appwrite refuses with `user_unauthorized` until an owner replaces the key.

~> **Note:** Appwrite requires an organization to keep at least one confirmed owner. It refuses to remove the `owner` role from the last owner, or to delete that owner's membership, and the apply fails with `membership_downgrade_prohibited` or `membership_deletion_prohibited`. Give another member the `owner` role first. Appwrite also refuses to remove the member whose payment method the organization is billed to. A change to `email` or `user_id` replaces the membership, and Terraform deletes the old one first, so replacing the only owner fails the same way. Use `create_before_destroy` to add the new membership first.

Appwrite Cloud plans limit how many members an organization can have. A create beyond the limit, or a project-specific role on a plan without them, fails with `billing_additional_resource_not_allowed`.

## Email addresses

`email` is the address the member was added with, and it is stored as written. Appwrite matches addresses without regard to case, so changing only the letter case updates state without replacing the membership. If the person later changes their account's address, `email` stays as it is and `user_email` shows the new address. Terraform does not treat that as a change.

`name` is only used when Appwrite creates an account for `email`. It is not read back, and changing it later updates state only.

## Example Usage

```terraform
# Add a member by email address. If no Appwrite account uses it, Appwrite
# creates one.
resource "appwrite_organization_membership" "jane" {
  email = "jane@example.com"
  roles = ["developer"]
}

# Add an existing account by its user ID.
resource "appwrite_organization_membership" "ops" {
  user_id = "6a3f1c2b0011aabbccdd"
  roles   = ["owner"]
}
```

## Schema

### Required

- `roles` (Set of String) The member's roles in the organization: owner, developer, editor, analyst or billing, or a project-specific role of the form project-{project_id}-{role} on plans that support them. Updated in place.

### Optional

- `email` (String) The email address of the member to add. When no Appwrite account uses it, Appwrite creates one. Kept as written; see user_email for the account's current address. Exactly one of email and user_id must be set. Changing this forces a new resource to be created. A change only in letter case does not.
- `name` (String) The name to give the account Appwrite creates when no account uses email. Ignored when the account already exists, and not read back. Changing it later updates state only.
- `organization_id` (String) The Appwrite organization ID. Defaults to the provider-level organization_id. Changing this forces a new resource to be created.
- `user_id` (String) The ID of an existing Appwrite account to add. Exactly one of email and user_id must be set. Changing this forces a new resource to be created.

### Read-Only

- `confirm` (Boolean) Whether the member has joined. Members added by Terraform join immediately; a membership imported while its invitation is pending is false until it is accepted.
- `id` (String) The membership ID.
- `joined_at` (String) When the member joined, in ISO 8601 format. Empty while an invitation is pending.
- `user_email` (String) The member account's current email address.
- `user_name` (String) The member account's name.

## Import

Using `terraform import` with an organization and membership ID:

```shell
terraform import appwrite_organization_membership.example organization-id/6a3f1c2b0011aabbccdd
```

When `organization_id` is configured on the provider, the membership ID alone can be used:

```shell
terraform import appwrite_organization_membership.example 6a3f1c2b0011aabbccdd
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_organization_membership.example
  id = "organization-id/6a3f1c2b0011aabbccdd"
}
```

An imported membership's `email` is the account's address as Appwrite stores it, in lowercase. If the configuration writes it in another case, the first plan after import shows an in-place update that changes only state. A membership whose invitation is still pending can be imported. Its `confirm` stays `false` until the invitation is accepted.
