# Resource: appwrite_domain_record

Manages a DNS record in the zone Appwrite hosts for an organization domain.

Domains are available on Appwrite Cloud. An organization API key with `domains.read` and `domains.write` scopes is required. Configure it with the provider's `organization_api_key` attribute or `APPWRITE_ORGANIZATION_API_KEY`. Set `organization_id` on the provider or on this resource.

The record's zone can belong to an [appwrite_domain](domain.md) resource, or to a domain read with the [appwrite_domain data source](../data-sources/domain.md). Records only resolve once the domain is delegated to Appwrite's nameservers.

Appwrite stores names relative to the domain, lowercase and without a trailing dot, and host name values lowercase without a trailing dot. `www`, `WWW` and `www.example.com.` are the same name, and the provider keeps whichever spelling the configuration uses. A zone holds each record once and a name holds at most one `CNAME`, so a duplicate is rejected when it is created.

`priority` is required for `MX` and `SRV` records, and `weight` and `port` for `SRV` records. They are rejected for other types. Changing `type`, `domain_id` or `organization_id` replaces the record; every other argument is updated in place.

Locked records, which Appwrite creates for its own routing, cannot be imported.

## Example Usage

```terraform
resource "appwrite_domain_record" "www" {
  domain_id = appwrite_domain.example.id
  type      = "A"
  name      = "www"
  value     = "203.0.113.10"
  ttl       = 300
}

resource "appwrite_domain_record" "mail" {
  domain_id = appwrite_domain.example.id
  type      = "MX"
  name      = "@"
  value     = "mx1.mail.example.net"
  priority  = 10
}

resource "appwrite_domain_record" "sip" {
  domain_id = appwrite_domain.example.id
  type      = "SRV"
  name      = "_sip._tcp"
  value     = "sip.example.net"
  priority  = 10
  weight    = 5
  port      = 5060
}

resource "appwrite_domain_record" "spf" {
  domain_id = appwrite_domain.example.id
  type      = "TXT"
  name      = "@"
  value     = "v=spf1 include:mail.example.net -all"
  comment   = "Mail provider SPF"
}
```

## Schema

### Required

- `domain_id` (String) The ID of the domain whose zone holds the record. Changing this forces a new resource to be created.
- `name` (String) The record name relative to the domain, such as www, or @ for the domain itself. A full name ending in the domain is also accepted. For SRV records, the service and protocol, such as _sip._tcp.
- `type` (String) The record type: A, AAAA, ALIAS, CAA, CNAME, HTTPS, MX, NS, SRV, TXT. Changing this forces a new resource to be created.
- `value` (String) The record value: an IPv4 address for A, an IPv6 address for AAAA, a host name for ALIAS, CNAME, MX, NS and SRV, a CAA value such as 0 issue "letsencrypt.org", or the text of a TXT record. TXT values may be up to 16384 characters, others up to 255.

### Optional

- `comment` (String) A comment explaining what the record is for.
- `organization_id` (String) The Appwrite organization ID. Defaults to the provider-level organization_id. Changing this forces a new resource to be created.
- `port` (Number) The port the SRV target serves on, from 0 to 65535. Required for SRV records and not accepted for other types.
- `priority` (Number) The record priority, from 0 to 65535. Lower values are tried first. Required for MX and SRV records and not accepted for other types.
- `ttl` (Number) Time to live, in seconds. Defaults to 3600.
- `weight` (Number) The weight used to share load between SRV targets of equal priority, from 0 to 65535. Required for SRV records and not accepted for other types.

### Read-Only

- `created_at` (String) The record creation timestamp in ISO 8601 format.
- `domain` (String) The name of the domain whose zone holds the record.
- `id` (String) The DNS record ID.
- `locked` (Boolean) Whether Appwrite manages the record. Locked records cannot be changed or deleted, so they cannot be managed by Terraform; a record this resource creates is never locked.
- `updated_at` (String) The record last update timestamp in ISO 8601 format.

## Import

Using `terraform import` with an organization, domain and record ID:

```shell
terraform import appwrite_domain_record.example organization-id/5ababd603b22780302dd8d83498e5172/6a1f0c2e000b3d7e9f42
```

When `organization_id` is configured on the provider, `domain_id/record_id` can be used:

```shell
terraform import appwrite_domain_record.example 5ababd603b22780302dd8d83498e5172/6a1f0c2e000b3d7e9f42
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_domain_record.example
  id = "organization-id/5ababd603b22780302dd8d83498e5172/6a1f0c2e000b3d7e9f42"
}
```

An import has no configuration to compare against, so it stores `name` and `value` as Appwrite returns them. If the configuration spells either differently, for example `www.example.com.` for a stored `www`, the first plan after the import shows an in-place update. Applying it sends the same record and changes nothing on the server; the plan is empty afterwards.
