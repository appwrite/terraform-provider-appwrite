# Resource: appwrite_auth_user_target

Manages a messaging target of an Appwrite user: an email address, phone number or push token that messages can be sent to, and that appwrite_messaging_subscriber can subscribe to a topic.

A target is where Appwrite delivers a message to a user. Appwrite creates one itself for a user's email address and one for their phone number, and keeps them in step with the user: changing the user's email or phone rewrites the target, and removing it deletes the target. Use this resource for any other destination, such as a second email address, a phone number that is not the user's login, or a device's push token.

## Identifiers

`identifier` must be unique across the project. That includes the targets Appwrite keeps for every user's email address and phone number, so a user's own email address cannot be added again as a target, and once a target holds an address, no user's email can be changed to it.

What `identifier` takes depends on `provider_type`, and it is checked at plan time:

- `email` takes an email address.
- `sms` takes a phone number in E.164 format: a leading `+`, a country code and at most 15 digits in all. Appwrite also rejects numbers whose country code it does not recognise, which is only reported when applying.
- `push` takes the device token the push provider issued. It is not checked.

Appwrite stores the identifier as written, including its case.

## Updates and replacement

`identifier`, `name` and `provider_id` are updated in place. Appwrite cannot clear `name` or `provider_id`, so removing either from the configuration replaces the target. Changing `user_id`, `provider_type`, `id` or `project_id` also replaces it.

Deleting a target deletes its subscriptions. When a replacement keeps the target ID, because `id` is set, the `appwrite_messaging_subscriber` resources pointing at it are not replanned, and Appwrite deletes their subscriptions in the background; the next plan recreates them. Add `replace_triggered_by` to the subscribers to recreate them in the same apply. When `id` is not set, a replacement generates a new ID and the subscribers are replaced with it.

Because identifiers are unique, a replacement that keeps the same `identifier` cannot use `create_before_destroy`.

When `provider_id` is set, Appwrite checks that the provider exists and is of the target's type. If it is not, the target has already been created when the error is reported. It is recorded as tainted and replaced on the next apply.

## Expired targets

When a push provider reports a device token as expired, Appwrite marks the target `expired`. Refreshing state shows the change without planning one. Set `identifier` to the device's new token to update it in place, which also clears `expired`.

Appwrite also has a cleanup that deletes expired targets. If it removes one, the next plan recreates it with the old token.

## Example Usage

```terraform
resource "appwrite_auth_user" "jane" {
  name  = "Jane Doe"
  email = "jane@example.com"
}

# A second address for Jane, delivered through a specific provider.
resource "appwrite_auth_user_target" "jane_alerts" {
  user_id       = appwrite_auth_user.jane.id
  provider_type = "email"
  identifier    = "jane.alerts@example.com"
  name          = "Alerts inbox"
  provider_id   = appwrite_messaging_provider.smtp.id
}

resource "appwrite_auth_user_target" "jane_phone" {
  user_id       = appwrite_auth_user.jane.id
  provider_type = "sms"
  identifier    = "+14155550100"
}

resource "appwrite_auth_user_target" "jane_device" {
  user_id       = appwrite_auth_user.jane.id
  provider_type = "push"
  identifier    = var.jane_device_token
  name          = "Jane's phone"
}

resource "appwrite_messaging_topic" "incidents" {
  name = "incidents"
}

resource "appwrite_messaging_subscriber" "jane_alerts" {
  topic_id  = appwrite_messaging_topic.incidents.id
  target_id = appwrite_auth_user_target.jane_alerts.id
}
```

## Schema

### Required

- `identifier` (String) Where messages are sent: an email address for `email`, a phone number in E.164 format for `sms`, or a device token for `push`. Must be unique across the project, including the email addresses and phone numbers of its users.
- `provider_type` (String) The kind of target: `email`, `sms` or `push`. Changing this forces a new resource to be created.
- `user_id` (String) The ID of the user the target belongs to. Changing this forces a new resource to be created.

### Optional

- `id` (String) The target ID. Generated when not set. Changing this forces a new resource to be created.
- `name` (String) A label for the target, such as the device a push token belongs to. Removing it forces a new resource to be created, because Appwrite cannot clear it.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `provider_id` (String) The ID of the messaging provider to send through, which must be of the same type as the target. When not set, Appwrite uses the project's first provider of that type. Removing it forces a new resource to be created, because Appwrite cannot clear it.

### Read-Only

- `created_at` (String) The target creation timestamp in ISO 8601 format.
- `expired` (Boolean) Whether a push provider has reported the device token as expired. Changing the identifier clears it.
- `updated_at` (String) The target last update timestamp in ISO 8601 format.

## Import

Import is supported using the user ID and the target ID:

```shell
terraform import appwrite_auth_user_target.jane_alerts <user-id>/<target-id>
```

The targets Appwrite keeps for a user's own email address and phone number cannot be imported, since Appwrite changes and deletes them along with the user. To subscribe one to a topic, pass its ID to `appwrite_messaging_subscriber` without managing it.
