# Resource: appwrite_domain_nameservers

Sets the registrar nameservers of a domain registered through Appwrite. Domains registered elsewhere have their nameservers set at that registrar; use appwrite_domain_nameservers_verification for those instead.

Only domains whose `registrar` is `appwrite` can have their nameservers set here; the API rejects any other. With `nameservers` omitted, the domain is delegated to Appwrite's nameservers, which is what lets Appwrite serve the records managed with [appwrite_domain_record](domain_record.md). With a list, the domain is delegated to those nameservers instead, and Appwrite's records stop resolving.

Domains are available on Appwrite Cloud. An organization API key with `domains.read` and `domains.write` scopes is required. Configure it with the provider's `organization_api_key` attribute or `APPWRITE_ORGANIZATION_API_KEY`. Set `organization_id` on the provider or on this resource.

~> **Note:** Appwrite does not report the nameservers a domain is delegated to, so this resource cannot detect a change made in the Console or at the registry. It sets the nameservers when it is created and whenever `nameservers` changes in configuration.

~> **Note:** Destroying this resource does not change the nameservers. The domain stays delegated where it was last set, and Terraform stops managing it.

## Example Usage

```terraform
data "appwrite_domain" "registered" {
  domain = "example.com"
}

# Delegate a domain registered through Appwrite to another DNS provider.
resource "appwrite_domain_nameservers" "example" {
  domain_id   = data.appwrite_domain.registered.id
  nameservers = ["ns1.dns.example.net", "ns2.dns.example.net"]
}
```

## Schema

### Required

- `domain_id` (String) The ID of a domain registered through Appwrite. Changing this forces a new resource to be created.

### Optional

- `nameservers` (List of String) The nameservers to delegate the domain to, at most 13. Omit to delegate it to Appwrite's nameservers, which is what lets Appwrite serve its DNS records. Appwrite does not report the nameservers it last set, so a change made outside Terraform is not detected.
- `organization_id` (String) The Appwrite organization ID. Defaults to the provider-level organization_id. Changing this forces a new resource to be created.

### Read-Only

- `id` (String) The domain ID.

## Import

Using `terraform import` with an organization and domain ID:

```shell
terraform import appwrite_domain_nameservers.example organization-id/5ababd603b22780302dd8d83498e5172
```

When `organization_id` is configured on the provider, the domain ID alone can be used.

Because the current nameservers cannot be read, an import leaves `nameservers` empty in state. If the configuration sets `nameservers`, the next apply sets them; if it omits them, the next apply changes nothing, even when the domain is delegated elsewhere.
