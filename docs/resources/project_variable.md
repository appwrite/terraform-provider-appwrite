# Resource: appwrite_project_variable

Manages an Appwrite project environment variable, shared by every function and site in the project.

A standard project API key with `project.read` and `project.write` scopes is required. The `functions.*` and `sites.*` scopes do not cover project variables. Configure the key with the provider's `api_key` attribute or `APPWRITE_API_KEY`.

~> **NOTE:** Appwrite makes a variable secret unless `secret = false` is set. A secret variable's value cannot be read back from the API, so a change made to it outside Terraform is not detected. A secret variable cannot be made non-secret again: changing `secret` from `true` to `false` deletes the variable and creates a new one.

When a function or site has its own variable with the same key ([appwrite_function_variable](function_variable.md), [appwrite_site_variable](site_variable.md)), its own value wins. Creating, updating or deleting a project variable marks every function and site in the project as needing a new deployment, as changing their own variables does.

## Example Usage

```terraform
# Shared by every function and site in the project.
resource "appwrite_project_variable" "api_url" {
  key    = "API_URL"
  value  = "https://api.example.com"
  secret = false
}

# Secret unless secret = false. With value_wo the value never reaches state;
# change value_wo_version to apply a new one. Requires Terraform 1.11 or later.
resource "appwrite_project_variable" "stripe_key" {
  key              = "STRIPE_SECRET_KEY"
  value_wo         = var.stripe_secret_key
  value_wo_version = 1
}
```

## Schema

### Required

- `key` (String) The variable key (name). Must be unique within the project. A function or site variable with the same key takes precedence over it.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `secret` (Boolean) Whether the variable is secret. Secret variables can only be updated or deleted, never read. Appwrite makes a variable secret unless this is set to false. A secret variable cannot be made non-secret again, so changing this from true to false forces a new resource to be created.
- `value` (String, Sensitive) The variable value. Stored in Terraform state; prefer value_wo, which is not. Exactly one of value or value_wo must be set.
- `value_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The variable value, as a write-only argument. Read from the configuration during apply and never persisted. Change value_wo_version to apply a new value, since Terraform cannot detect a change in a value it does not store. Requires Terraform 1.11 or later.
- `value_wo_version` (Number) Increment to apply a changed value_wo.

### Read-Only

- `created_at` (String) The variable creation timestamp in ISO 8601 format.
- `id` (String) The variable ID.
- `updated_at` (String) The variable last update timestamp in ISO 8601 format.

## Import

Using `terraform import` with a variable ID, for a variable in the provider's default project:

```shell
terraform import appwrite_project_variable.example 69da24c7747e5c2cdfc4
```

For a variable in another project, use the project and variable ID:

```shell
terraform import appwrite_project_variable.example project-id/69da24c7747e5c2cdfc4
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_project_variable.example
  id = "project-id/variable-id"
}
```

The value is not imported. Set `value` or `value_wo` in the configuration, and the first apply after the import writes it to the variable.
