# Resource: appwrite_proxy_rule

Manages a custom domain proxy rule: serving an Appwrite site, function or the Appwrite API on a domain, or redirecting a domain to a URL.

A standard project API key with `rules.read` and `rules.write` scopes is required. Configure it with the provider's `api_key` attribute or `APPWRITE_API_KEY`.

## Example Usage

```terraform
resource "appwrite_site" "example" {
  name          = "example-site"
  framework     = "other"
  build_runtime = "node-22"
}

# Serve a site on a custom domain.
resource "appwrite_proxy_rule" "example" {
  domain      = "www.example.com"
  type        = "site"
  resource_id = appwrite_site.example.id
}

# Serve the Appwrite API on a custom domain.
resource "appwrite_proxy_rule" "api" {
  domain = "api.example.com"
  type   = "api"
}

# Redirect the apex domain to the site, listed under the site's domains.
resource "appwrite_proxy_rule" "apex" {
  domain                 = "example.com"
  type                   = "redirect"
  redirect_url           = "https://www.example.com"
  redirect_status_code   = 301
  resource_id            = appwrite_site.example.id
  redirect_resource_type = "site"
}
```

## Rule Types

| `type` | What the domain does | Arguments |
|---|---|---|
| `site` | Serves a site. | `resource_id` (the site ID), optional `branch` |
| `function` | Executes a function. | `resource_id` (the function ID), optional `branch` |
| `api` | Serves the Appwrite API. | none |
| `redirect` | Redirects every request to `redirect_url`. | `redirect_url`, `redirect_status_code`, `resource_id`, `redirect_resource_type` |

Each type's arguments are checked at plan time: a missing one, or one the type does not use, fails the plan.

A `redirect` rule belongs to a site or function, named by `resource_id` and `redirect_resource_type`. The rule is listed among that resource's domains in the Console, and Appwrite deletes it when the site or function is deleted. Terraform then plans to create the rule again.

Appwrite cannot update a rule, so changing any argument replaces it.

## Domain Verification

Appwrite checks the domain's DNS records when the rule is created. If they do not point at Appwrite yet, the rule is still created, with `status` set to `unverified` and the reason in `logs`. Retry verification from the Console once DNS is in place; Terraform does not retry it.

## Schema

### Required

- `domain` (String) The custom domain name. Changing this forces a new resource to be created.
- `type` (String) What the rule does: `site` or `function` serves that resource on the domain, `api` serves the Appwrite API, and `redirect` redirects to `redirect_url`. Changing this forces a new resource to be created.

### Optional

- `branch` (String) The VCS branch that updates the rule automatically. Only for `site` and `function` rules. Changing this forces a new resource to be created.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `redirect_resource_type` (String) The type of the resource named by `resource_id` on a `redirect` rule: `site` or `function`. Required for `redirect` rules and not used by any other type. Changing this forces a new resource to be created.
- `redirect_status_code` (Number) The HTTP status code a `redirect` rule responds with: 301, 302, 307 or 308. Required for `redirect` rules and not used by any other type. Changing this forces a new resource to be created.
- `redirect_url` (String) The absolute URL a `redirect` rule redirects to. Required for `redirect` rules and not used by any other type. Changing this forces a new resource to be created.
- `resource_id` (String) The ID of the site or function served by this rule. For a `redirect` rule, the site or function the rule is listed under, whose deletion also deletes the rule. Required for every type except `api`, which does not take it. Changing this forces a new resource to be created.

### Read-Only

- `created_at` (String) The rule creation timestamp in ISO 8601 format.
- `id` (String) The proxy rule ID.
- `logs` (String) Domain verification or certificate generation logs.
- `renew_at` (String) The certificate auto-renewal timestamp in ISO 8601 format.
- `status` (String) The domain verification status.
- `updated_at` (String) The rule last update timestamp in ISO 8601 format.

## Import

Using `terraform import` with a project and rule ID:

```shell
terraform import appwrite_proxy_rule.example project-id/d9b2824f455601ef3ff9f8147c5f186c
```

When `project_id` is configured on the provider, the rule ID alone can be used:

```shell
terraform import appwrite_proxy_rule.example d9b2824f455601ef3ff9f8147c5f186c
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_proxy_rule.example
  id = "project-id/d9b2824f455601ef3ff9f8147c5f186c"
}
```

On installations configured to use MD5 rule IDs, the ID is `md5(lower(domain))`. Always prefer the ID returned by the API because some Community Edition installations use generated IDs.
