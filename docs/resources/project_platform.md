# Resource: appwrite_project_platform

Manages a platform of an Appwrite project: a web app, or an Android, Apple, Linux or Windows app, allowed to call the project's APIs from a client SDK.

Appwrite only accepts client SDK requests from the platforms a project lists: a web app by the host name it is served from, a native app by its application ID, bundle identifier or package name.

A standard project API key with `platforms.read` and `platforms.write` scopes is required. Configure it with the provider's `api_key` attribute or `APPWRITE_API_KEY`.

`type` picks the platform and the one argument it takes:

| `type` | Argument |
| --- | --- |
| `web` | `hostname` |
| `android` | `application_id` |
| `apple` | `bundle_identifier` |
| `linux` | `package_name` |
| `windows` | `package_identifier_name` |

The argument for the chosen type is required and the others are rejected. Changing `type`, `id` or `project_id` replaces the platform; `name` and the type's argument are updated in place. Appwrite stores both as written, without changing case or trimming spaces.

Platform IDs are unique across the whole Appwrite instance, not only within the project. Leave `id` unset to have one generated; a custom ID that another project already uses is rejected, which on Appwrite Cloud includes projects of other organizations.

## Example Usage

```terraform
resource "appwrite_project_platform" "web" {
  type     = "web"
  name     = "Web app"
  hostname = "app.example.com"
}

# A leading wildcard allows every subdomain, such as preview deployments.
resource "appwrite_project_platform" "previews" {
  type     = "web"
  name     = "Preview deployments"
  hostname = "*.preview.example.com"
}

resource "appwrite_project_platform" "android" {
  type           = "android"
  name           = "Android app"
  application_id = "com.example.app"
}

resource "appwrite_project_platform" "ios" {
  type              = "apple"
  name              = "iOS app"
  bundle_identifier = "com.example.app"
}

resource "appwrite_project_platform" "linux" {
  type         = "linux"
  name         = "Linux app"
  package_name = "example-app"
}

resource "appwrite_project_platform" "windows" {
  type                    = "windows"
  name                    = "Windows app"
  package_identifier_name = "Example.App"
}
```

## Schema

### Required

- `name` (String) The platform name. At most 128 characters.
- `type` (String) The platform type: web, android, apple, linux, windows. Changing this forces a new resource to be created.

### Optional

- `application_id` (String) The Android application ID, such as com.example.app. Required for android platforms and not accepted for other types. At most 255 characters.
- `bundle_identifier` (String) The Apple bundle identifier, such as com.example.app. Required for apple platforms and not accepted for other types. At most 255 characters.
- `hostname` (String) The host name the web app is served from, such as app.example.com, without a scheme, port or path. A leading wildcard such as *.example.com allows every subdomain, though not example.com itself. Required for web platforms and not accepted for other types. At most 253 characters.
- `id` (String) The platform ID. Generated when not set. Platform IDs are unique across the whole Appwrite instance, not only the project, so a custom ID another project uses is rejected. Changing this forces a new resource to be created.
- `package_identifier_name` (String) The Windows package identifier name. Required for windows platforms and not accepted for other types. At most 255 characters.
- `package_name` (String) The Linux package name. Required for linux platforms and not accepted for other types. At most 255 characters.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.

### Read-Only

- `created_at` (String) The platform creation timestamp in ISO 8601 format.
- `updated_at` (String) The platform last update timestamp in ISO 8601 format.

## Import

Using `terraform import` with a project and platform ID:

```shell
terraform import appwrite_project_platform.example project-id/6a1f0c2e000b3d7e9f42
```

When `project_id` is configured on the provider, the platform ID alone can be used:

```shell
terraform import appwrite_project_platform.example 6a1f0c2e000b3d7e9f42
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_project_platform.example
  id = "project-id/6a1f0c2e000b3d7e9f42"
}
```

A platform created before Appwrite merged its platform types, under a type such as `flutter-ios` or `react-native-android`, imports under the merged type (`apple`, `android`). Appwrite cannot update an app platform like that in place, so changing its name or identifier fails with `platform_method_unsupported`; replace it instead, for example with `terraform apply -replace`. Former web types such as `flutter-web` update normally.
