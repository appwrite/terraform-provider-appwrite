# Resource: appwrite_project_auth_policies

Manages a project's password, session, user, team membership, MFA and sign-up email policies. Every project has these settings, so creating this resource takes them over rather than creating anything, and destroying it resets them to Appwrite's defaults. An attribute left out of the configuration is set to its default too. Use one per project: two would overwrite each other.

A standard project API key with `project.policies.read` and `project.policies.write` scopes is required. Keys with the older `policies.read` and `policies.write` scopes also work. Configure it with the provider's `api_key` attribute or `APPWRITE_API_KEY`.

~> **Note:** This resource is authoritative for every policy it lists. An attribute left out of the configuration is set to its default on the next apply, so a policy changed in the Console is changed back unless the configuration sets it too. Import the resource first to see the current settings in the plan.

The defaults are the values Appwrite gives a new project:

| Policy | Default |
| --- | --- |
| `password_dictionary`, `password_personal_data` | `false` |
| `password_history` | `0`, no history |
| `password_strength` | `min = 8`, nothing else required |
| `password_pwned` | `enabled = true`, `users = false`, `sessions = false` |
| `session_alert` | `false` |
| `session_duration` | `31536000`, one year |
| `session_invalidation` | `true` |
| `session_limit` | `10` |
| `user_limit` | `0`, no limit |
| `membership_privacy` | every field `false` |
| `mfa_factors` | `totp`, `email` and `phone` `true`, `custom` `false` |
| `deny_aliased_email`, `deny_disposable_email`, `deny_free_email`, `deny_corporate_email` | `false` |

The password and email policies are checked whenever a user is created or changes their password or email address, including through the Users API with an API key.

~> **Note:** `password_pwned` needs Appwrite 2.3.0 or later. Against an older server it must be left out or set to its defaults; any other value fails to apply before any other policy is changed.

On Appwrite Cloud, the sign-up email policies are enforced only on plans that include them; the setting is stored either way.

## Example Usage

```terraform
# Anything not set here is kept at, or returned to, Appwrite's default.
resource "appwrite_project_auth_policies" "example" {
  password_dictionary    = true
  password_history       = 5
  password_personal_data = true

  password_strength = {
    min       = 12
    uppercase = true
    number    = true
  }

  session_duration = 86400 # one day
  session_limit    = 5

  mfa_factors = {
    phone = false
  }

  deny_disposable_email = true
}
```

## Schema

### Optional

- `deny_aliased_email` (Boolean) Whether signing up or changing email address is refused for an aliased address, such as one with a `+` suffix. Defaults to `false`.
- `deny_corporate_email` (Boolean) Whether signing up or changing email address is restricted to corporate addresses, refusing addresses at free or disposable email domains. Despite the name, which follows Appwrite's policy ID, it is non-corporate addresses that are denied. Defaults to `false`.
- `deny_disposable_email` (Boolean) Whether signing up or changing email address is refused for an address at a known disposable email domain. Defaults to `false`.
- `deny_free_email` (Boolean) Whether signing up or changing email address is refused for an address at a free email provider such as Gmail or Yahoo. Defaults to `false`.
- `membership_privacy` (Attributes) Which details of a team member the other members of the team can see. Leaving it out sets every field to its default. (see [below for nested schema](#nestedatt--membership_privacy))
- `mfa_factors` (Attributes) Which factors users can complete an MFA challenge with. Recovery codes always remain available. Leaving it out sets every field to its default. (see [below for nested schema](#nestedatt--mfa_factors))
- `password_dictionary` (Boolean) Whether a new password is rejected when it is one of the 10,000 most common passwords. Existing passwords stay valid. Defaults to `false`.
- `password_history` (Number) How many of a user's previous passwords they cannot reuse, from 1 to 20, or `0` to keep no history. Passwords are only recorded while the history is kept, so turning it on does not cover passwords set before. Defaults to `0`.
- `password_personal_data` (Boolean) Whether a new password is rejected when it contains the user's ID, name, email address or phone number. Existing passwords stay valid. Defaults to `false`.
- `password_pwned` (Attributes) Checks passwords against the Have I Been Pwned breach database. Only the first five characters of the password's hash are sent to it. Requires Appwrite 2.3.0 or later; against an older server, any value other than the defaults fails to apply. Leaving it out sets every field to its default. (see [below for nested schema](#nestedatt--password_pwned))
- `password_strength` (Attributes) What a new password must contain. Leaving it out sets every field to its default. (see [below for nested schema](#nestedatt--password_strength))
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `session_alert` (Boolean) Whether a user is emailed when a new session is created for them. The first session after signing up does not send one. Defaults to `false`.
- `session_duration` (Number) How long a session lasts, in seconds, from 60 to 31536000 (one year). Defaults to `31536000`.
- `session_invalidation` (Boolean) Whether changing a user's password ends their existing sessions. Defaults to `true`.
- `session_limit` (Number) The most sessions a user can have at once, from 1 to 100. Creating one more deletes the oldest. Defaults to `10`.
- `user_limit` (Number) The most users the project can have, from 1 to 10000, or `0` for no limit. Reaching it stops new sign-ups; existing users are not affected. Defaults to `0`.

## Import

Using `terraform import` with a project ID:

```shell
terraform import appwrite_project_auth_policies.example project-id
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_project_auth_policies.example
  id = "project-id"
}
```
