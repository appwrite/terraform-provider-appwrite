# Resource: appwrite_project_email_template

Manages a project's custom email template for one type of email in one locale. Appwrite uses custom templates only while the project's custom SMTP is enabled.

Every type of email has a default template in every locale, so this resource replaces the default rather than creating anything. Appwrite picks the template for the user's locale when it sends the email.

A project API key with the `templates.read` and `templates.write` scopes is required.

~> **Note:** Appwrite accepts a custom template only while the project's custom SMTP is enabled, and uses custom templates only while it stays enabled. Manage it with [appwrite_project_smtp](project_smtp.md) and add that resource to `depends_on`, so Terraform enables SMTP first.

!> **Warning:** Destroying this resource does not restore the default template. Appwrite has no API a project key can use to remove a custom template, so it keeps its last applied content, Terraform warns and stops managing it. Reset it in the Appwrite Console to restore the default. Disabling custom SMTP also stops Appwrite from using it.

`subject` and `message` can use the placeholders Appwrite fills in when it sends the email, such as `{{user}}`, `{{project}}` and `{{redirect}}`. The placeholders available depend on the type of email; see the [Appwrite documentation](https://appwrite.io/docs/advanced/platform/message-templates).

## Example Usage

```terraform
resource "appwrite_project_email_template" "verification" {
  type    = "verification"
  locale  = "en"
  subject = "Verify your {{project}} account"
  message = <<-HTML
    <p>Hello {{user}},</p>
    <p>Follow <a href="{{redirect}}">this link</a> to verify your email address.</p>
    <p>The {{project}} team</p>
  HTML

  # Appwrite accepts custom templates only while custom SMTP is enabled.
  depends_on = [appwrite_project_smtp.example]
}

resource "appwrite_project_email_template" "verification_pt_br" {
  type        = "verification"
  locale      = "pt-br"
  subject     = "Confirme sua conta {{project}}"
  message     = "<p>Olá {{user}}, confirme seu e-mail: <a href=\"{{redirect}}\">{{redirect}}</a></p>"
  sender_name = "Equipe Example"

  depends_on = [appwrite_project_smtp.example]
}
```

## Schema

### Required

- `locale` (String) The locale the template is for, such as en or pt-br. Changing this forces a new resource to be created.
- `message` (String) The email's body, as plain text or HTML. Appwrite fills in placeholders such as {{user}}, {{project}} and {{redirect}} when it sends the email.
- `subject` (String) The email's subject.
- `type` (String) The email the template is for: verification, magicSession, recovery, invitation, mfaChallenge, sessionAlert or otpSession. Changing this forces a new resource to be created.

### Optional

- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `reply_to_email` (String) The email address replies go to, overriding the SMTP configuration's reply_to_email.
- `reply_to_name` (String) The name replies go to, overriding the SMTP configuration's reply_to_name.
- `sender_email` (String) The email address the email is sent from, overriding the SMTP configuration's sender_email.
- `sender_name` (String) The name the email is sent from, overriding the SMTP configuration's sender_name.

### Read-Only

- `id` (String) The template's ID, in the form type/locale.

## Import

Import uses the format `project_id/type/locale`:

```shell
terraform import appwrite_project_email_template.verification project-id/verification/en
```

When `project_id` is configured on the provider, `type/locale` alone can be used. Only a customized template can be imported; one still on Appwrite's default has nothing to import.

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_project_email_template.verification
  id = "project-id/verification/en"
}
```
