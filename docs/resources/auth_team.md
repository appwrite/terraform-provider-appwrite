# Resource: appwrite_auth_team

Manages an Appwrite team.

## Example Usage

```terraform
resource "appwrite_auth_team" "engineering" {
  name = "engineering"
}

resource "appwrite_auth_team" "marketing" {
  name  = "marketing"
  roles = ["owner", "editor"]
}

# Preferences shared by every member. Leave prefs out to keep whatever the
# team already has.
resource "appwrite_auth_team" "support" {
  name = "support"
  prefs = jsonencode({
    timezone = "Europe/Amsterdam"
    sla      = { response_hours = 4 }
  })
}
```

## Schema

### Required

- `name` (String) The team name.

### Optional

- `id` (String) The team ID. Changing this forces a new resource to be created.
- `prefs` (String) The team's preferences, shared by every member, as a JSON-encoded object. Use jsonencode to write it and jsondecode to read it. When omitted, Terraform leaves the preferences as they are and reports what the server holds. Setting it replaces the whole object. Appwrite does not accept an empty object, so preferences cannot be cleared once set: "{}" is rejected at plan time for a team that has preferences.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `roles` (List of String) Roles for new team members. Defaults to ["owner"].

### Read-Only

- `created_at` (String) The team creation timestamp in ISO 8601 format.
- `updated_at` (String) The team last update timestamp in ISO 8601 format.
