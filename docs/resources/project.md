# Resource: appwrite_project

Manages an Appwrite project within an organization.

~> **Warning:** Destroying a project also deletes the resources and data contained in it.

An organization-scoped API key with `projects.read` and `projects.write` scopes is required. Set `organization_id` on the provider or on this resource. A provider-level `project_id` is not required.

## Example Usage

```terraform
resource "appwrite_project" "example" {
  id     = "example-project"
  name   = "Example Project"
  region = "fra"
}
```

## Schema

### Required

- `name` (String) The project name.

### Optional

- `id` (String) The project ID.
- `organization_id` (String) The Appwrite organization ID. Defaults to the provider-level organization_id.
- `region` (String) The region where the project is hosted. Defaults to the server's configured region.

### Read-Only

- `created_at` (String) The project creation timestamp in ISO 8601 format.
- `status` (String) The project status.
- `team_id` (String) The ID of the team that owns the project.
- `updated_at` (String) The project last update timestamp in ISO 8601 format.

## Import

Using `terraform import` with an organization and project ID:

```shell
terraform import appwrite_project.example organization-id/example-project
```

When `organization_id` is configured on the provider, the project ID alone can be used:

```shell
terraform import appwrite_project.example example-project
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_project.example
  id = "organization-id/example-project"
}
```
