# Resource: appwrite_monitor

Manages a monitor on an Appwrite project: an HTTP, DNS, TCP or SMTP probe of a target, or a check of the project's usage, that opens an alert when its rules match.

One resource covers every monitor type, as `appwrite_waf_rule` and `appwrite_messaging_provider` do: `type` picks the type, and each type takes its own arguments. `http`, `dns`, `tcp` and `smtp` monitors probe a target on their own interval and are available on Appwrite Cloud. `usage` monitors compare a usage metric of the project, or of one of its databases, buckets, functions or sites, with a threshold, and need an Appwrite that serves the monitors API.

A standard project API key with `monitors.read` and `monitors.write` scopes is required. Configure it with the provider's `api_key` attribute or `APPWRITE_API_KEY`.

When a monitor fires it opens an alert, fires the `monitors.[monitorId].alerts.[alertId].create` event for webhooks, functions and realtime, and notifies the `notify` roles, or the steps of the [appwrite_escalation](escalation.md) named by `escalation_id`. Alerts are records of what happened rather than configuration, so the provider does not manage them.

## Rules

`rules` are query strings that must all hold for the monitor to fire. Write each with `jsonencode`, in the shape the Appwrite SDKs' `Query` class produces:

```terraform
rules = [
  jsonencode({ method = "greaterThan", attribute = "network.outbound", values = [5000000000] }),
  jsonencode({ method = "equal", attribute = "resourceType", values = ["buckets"] }),
  jsonencode({ method = "equal", attribute = "resourceId", values = ["avatars"] }),
]
```

Appwrite stores each rule re-encoded. The provider keeps the rules as written when the stored ones mean the same, so key order, number formatting and the order of the rules do not show as a diff.

A `usage` monitor needs one rule comparing a metric, named as the usage endpoints name it, with a threshold in the metric's unit. A probe monitor without `rules` uses its type's defaults: an `http` monitor fires on a status code outside 200 to 299 or a certificate close to expiry, a `dns` monitor when there is no answer, and `tcp` and `smtp` monitors on connection failures. The defaults are not recorded in state, and removing `rules` from a probe monitor puts them back.

`interval` reads back raised to the shortest interval the organization's plan allows, so set it no lower than that.

Changing `type`, `id` or `project_id` replaces the monitor and with it its alert history. Every other argument is updated in place, and only the arguments that changed are sent.

## Example Usage

```terraform
resource "appwrite_monitor" "api" {
  type = "http"
  name = "API health"
  url  = "https://api.example.com/health"

  headers = {
    Authorization = "Bearer ${var.health_token}"
  }

  rules = [
    jsonencode({ method = "notBetween", attribute = "statusCode", values = [200, 299] }),
    jsonencode({ method = "greaterThan", attribute = "latency", values = [2000] }),
  ]

  interval      = 60
  severity      = "critical"
  escalation_id = appwrite_escalation.on_call.id
}

resource "appwrite_monitor" "database" {
  type = "tcp"
  name = "Database port"
  host = "db.example.com"
  port = 5432
}

resource "appwrite_monitor" "bandwidth" {
  type = "usage"
  name = "Bandwidth over 5 GB a day"

  rules = [
    jsonencode({ method = "greaterThan", attribute = "network.outbound", values = [5000000000] }),
  ]

  window = 86400
  notify = ["owner", "developer"]
}

variable "health_token" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `name` (String) The monitor name, up to 128 characters.
- `type` (String) What the monitor checks: `http`, `dns`, `tcp` and `smtp` probe a target on their own interval, and `usage` compares a usage metric with a threshold. Changing this forces a new resource to be created.

### Optional

- `body` (String) The request body an http monitor sends, up to 16384 characters. Not accepted for other types.
- `cooldown` (Number) Minimum seconds between two team notifications of the monitor firing, from 300 to 2592000. Alert events fire on every change regardless. Defaults to 3600.
- `domain` (String) The domain a dns monitor queries, such as example.com. Required for dns monitors; not accepted for other types.
- `enabled` (Boolean) Whether the monitor is evaluated. Defaults to true.
- `escalation_id` (String) The ID of an escalation of the organization, such as an appwrite_escalation, that notifies the team step by step until a member acknowledges the alert. When set, notify is not used. Defaults to empty, which notifies the notify roles once.
- `headers` (Map of String, Sensitive) HTTP headers an http monitor sends, as a map of header names and values. Not accepted for other types.
- `host` (String) The hostname or IP address a tcp or smtp monitor connects to. Required for tcp and smtp monitors; not accepted for other types.
- `id` (String) The monitor ID. Generated when not set. Changing this forces a new resource to be created.
- `interval` (Number) Seconds between two checks of a probe monitor, from 1 to 2592000. Defaults to 60, or to the shortest interval the organization's plan allows when that is longer; left out, an existing monitor keeps its interval. Not accepted for usage monitors.
- `method` (String) The HTTP method an http monitor requests the URL with: GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS. Defaults to GET for http monitors; not accepted for other types.
- `notify` (List of String) Organization roles, such as owner or developer, whose confirmed members get an email and a console notification when the monitor fires and resolves. An empty list leaves the alert events as the only delivery. Not used while escalation_id is set. Defaults to `["owner"]`.
- `port` (Number) The port a tcp or smtp monitor connects to, from 1 to 65535. Required for tcp and smtp monitors; not accepted for other types.
- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id. Changing this forces a new resource to be created.
- `record` (String) The record type a dns monitor queries: A, AAAA, CNAME, MX, TXT, NS. Defaults to A for dns monitors; not accepted for other types.
- `resolver` (String) The resolver a dns monitor queries, as an IP address with an optional port, such as 1.1.1.1 or [2606:4700:4700::1111]:53. Left out, the server's resolver is used. Not accepted for other types.
- `rules` (List of String) Rules that must all hold for the monitor to fire, each a query string usually written with jsonencode, such as jsonencode({ method = "greaterThan", attribute = "latency", values = [500] }). A usage monitor needs one comparing a usage metric with a threshold, and may add equal rules on resourceType and resourceId to watch one database, bucket, function or site. Probe monitors compare variables of the check: statusCode, latency, certificateDays and certificateLifetime for http; answer, answers and latency for dns; latency for tcp; code, latency, certificateDays and certificateLifetime for smtp. Required for usage monitors. Left out, a probe monitor uses its type's default rules, which are not recorded in state.
- `severity` (String) How urgent the monitor's alerts are: info, warning, error, critical. Defaults to warning.
- `timeout` (Number) Seconds a probe monitor's check may take before it fails, from 1 to 60, and no longer than interval. Defaults to 10 for probe monitors; not accepted for usage monitors.
- `tls_mode` (String) How an smtp monitor secures the connection: auto (implicit on port 465, starttls on 587 and none otherwise), none, starttls or implicit. Defaults to auto for smtp monitors; not accepted for other types.
- `url` (String) The URL an http monitor requests, with an http or https scheme. Required for http monitors; not accepted for other types.
- `window` (Number) Seconds a usage monitor sums a counter metric over, from 60 to 2592000. Gauges compare their latest value. Defaults to 3600 for usage monitors; not accepted for other types.

### Read-Only

- `created_at` (String) The monitor creation timestamp in ISO 8601 format.
- `status` (String) Whether the monitor is firing, as of its last evaluation.
- `updated_at` (String) The monitor last update timestamp in ISO 8601 format.

## Import

Using `terraform import` with a project and monitor ID:

```shell
terraform import appwrite_monitor.api project-id/api-health
```

When `project_id` is configured on the provider, the monitor ID alone can be used:

```shell
terraform import appwrite_monitor.api api-health
```

Using an import block (Terraform v1.5.0+):

```hcl
import {
  to = appwrite_monitor.api
  id = "project-id/api-health"
}
```
