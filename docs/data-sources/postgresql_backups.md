# Data Source: appwrite_postgresql_backups

Lists the backups taken of a dedicated Appwrite PostgreSQL database. Restoring is not a Terraform operation, so this is how a backup ID is found for a restore run through the Console or API.

## Example Usage

```terraform
data "appwrite_postgresql_backups" "main" {
  database_id = "main"

  queries = [
    "equal(\"status\", \"completed\")",
    "orderDesc(\"$createdAt\")",
    "limit(10)",
  ]
}

# Restoring is not a Terraform operation, so this is how a backup ID is found
# for a restore run through the Console or API.
output "latest_backup_id" {
  value = try(data.appwrite_postgresql_backups.main.backups[0].id, null)
}

output "recent_backups" {
  value = [
    for b in data.appwrite_postgresql_backups.main.backups : {
      id           = b.id
      type         = b.type
      size_bytes   = b.size_bytes
      completed_at = b.completed_at
    }
  ]
}

# A backup whose type differs from what was requested fell back; fallback_reason
# explains why, and is worth surfacing rather than silently accepting.
output "fell_back" {
  value = [
    for b in data.appwrite_postgresql_backups.main.backups :
    "${b.id}: wanted ${b.requested_type}, got ${b.type} (${b.fallback_reason})"
    if b.fallback_reason != ""
  ]
}
```

## Schema

### Required

- `database_id` (String) The dedicated database ID.

### Optional

- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id.
- `queries` (List of String) Appwrite query strings used to filter the listing, for example `equal("status", "completed")`.

### Read-Only

- `backups` (Attributes List) The backups that matched. (see [below for nested schema](#nestedatt--backups))
- `total` (Number) The total number of backups matching the query.

### Nested Schema for `backups`

Read-Only:

- `completed_at` (String) When the backup finished, in ISO 8601 format.
- `created_at` (String) The creation timestamp in ISO 8601 format.
- `error` (String) The error message when the backup failed.
- `expires_at` (String) When the backup expires, in ISO 8601 format.
- `fallback_reason` (String) Why the backend ran a different type than requested. Empty when it ran as requested.
- `id` (String) The backup ID.
- `log_position` (String) The transaction-log position the backup anchors at, in the engine's own notation. Empty for backup types that carry none.
- `policy_id` (String) The policy that produced the backup, when it came from a schedule.
- `requested_type` (String) The backup type that was asked for. Differs from `type` when the backend could not run it and fell back.
- `size_bytes` (Number) The backup size in bytes.
- `started_at` (String) When the backup started, in ISO 8601 format.
- `status` (String) `pending`, `running`, `completed`, `failed` or `verified`.
- `trigger` (String) What started the backup: `manual` or `schedule`.
- `type` (String) The backup type that ran: `full`, `incremental` or `wal`.
- `verified_at` (String) When the backup was verified, in ISO 8601 format.
