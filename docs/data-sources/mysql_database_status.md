# Data Source: appwrite_mysql_database_status

Reads the live operational state of a dedicated Appwrite MySQL database: health, replication, connection counts and storage volumes.

These are measurements taken when Terraform refreshes, not configuration, so they change between runs on their own. Use them for outputs and checks, not to drive resource arguments.

## Example Usage

```terraform
data "appwrite_mysql_database_status" "main" {
  database_id = "main"
}

# Measurements taken at refresh time, not configuration, so they change between
# runs on their own.
output "health" {
  value = data.appwrite_mysql_database_status.main.health
}

check "database_is_healthy" {
  assert {
    condition     = data.appwrite_mysql_database_status.main.ready
    error_message = "The main MySQL database is not accepting connections."
  }
}
```

## Schema

### Required

- `database_id` (String) The dedicated database ID.

### Optional

- `project_id` (String) The Appwrite project ID. Defaults to the provider-level project_id.

### Read-Only

- `connections_current` (Number) The current number of active connections.
- `connections_max` (Number) The engine's own max_connections. On a pooled database this is the backend limit the pooler multiplexes onto, not the ceiling a client pool may reach.
- `effective_sync_mode` (String) The sync mode the primary is actually enforcing. Empty when high availability is disabled or the state could not be read.
- `engine` (String) The database engine.
- `health` (String) Overall health: `healthy`, `degraded`, `unhealthy`, or `unknown` when nothing could be measured.
- `ready` (Boolean) Whether the database is ready to accept connections.
- `replicas` (Attributes List) Every configured member, including one the backend has not brought up, which is reported as not healthy. (see [below for nested schema](#nestedatt--replicas))
- `sync_acknowledgements` (Number) How many standby acknowledgements the primary waits for before committing a write.
- `sync_degraded` (Boolean) Whether the enforced replication is weaker than the requested `sync_mode`.
- `sync_mode` (String) The requested replication sync mode.
- `sync_standby_count` (Number) How many standbys are registered with the primary for synchronous replication.
- `sync_state_confirmed` (Boolean) Whether the sync fields are an engine reading rather than a recorded estimate. False means no reading was taken, not that replication is unhealthy — draw no conclusion about replication health from it.
- `uptime` (Number) Uptime in seconds.
- `version` (String) The engine version.
- `volumes` (Attributes List) The storage volumes backing the database. (see [below for nested schema](#nestedatt--volumes))

<a id="nestedatt--replicas"></a>
### Nested Schema for `replicas`

Read-Only:

- `healthy` (Boolean) Whether the member is healthy.
- `index` (Number) The member index. Read `role` for which member accepts writes: a failover moves the primary without renumbering.
- `lag_seconds` (Number) Replication lag in seconds. 0 for the primary, and for a streaming member whose engine printed no numeric lag.
- `replicating` (Boolean) Whether the member is streaming from the primary. False for a primary, which has no stream to report, and for an unhealthy member, which is not probed.
- `role` (String) `primary`, `replica`, or `unknown` while a transition is moving the topology.

### Nested Schema for `volumes`

Read-Only:

- `mounted` (Boolean) Whether the volume is mounted.
- `path` (String) The mount path.
- `used_percent` (String) The percentage of storage used.
